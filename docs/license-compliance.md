# Licence compliance

Ilavrita is distributed under the [AGPL-3.0](../LICENSE) and is scanned by the
[FOSSA GitHub App](https://app.fossa.com/projects/git%2Bgithub.com%2FIlavrita%2FIlavrita)
on every push and pull request.

This page records what the scanner reports and what we concluded, so a flagged
dependency is either fixed or explained — never silently ignored.

It is an engineering determination, not legal advice.

## Current state

The FOSSA checks on pull requests are **red**: 27 licence issues and 1
vulnerability. Of those 28: seventeen relate to `modernc.org/libc` and are an open licensing
question, one is a genuine security advisory, and ten are scanner artefacts
(including two that are simply Ilavrita's own licence). None can be cleared from this repository —
see [clearing them](#clearing-them).

| Group | Count | Verdict |
| --- | --- | --- |
| Ilavrita's own AGPL-3.0 licence | 2 | Not a finding — this is the project's chosen licence |
| `modernc.org/libc@v1.74.4` | 17 | **Open question** — glibc-derived LGPL-2.1 headers reach the Linux release |
| `golang.org/x/text@v0.42.0` | 4 | Reviewed — module is BSD-3-Clause |
| `modernc.org/sqlite@v1.57.0` | 3 | Reviewed — module is BSD-3-Clause |
| `golang.org/x/crypto@v0.57.0` | 1 | Reviewed — module is BSD-3-Clause |
| `github.com/disintegration/imaging@v1.6.2` | 1 | **Genuine.** CVE-2023-36308, no fixed version |

### The two self-flags

FOSSA flags `AGPL-3.0-only` and `AGPL-3.0-or-later` **on Ilavrita itself**. The
project is deliberately AGPL-3.0; this is the policy reporting our own licence
back to us, not a dependency risk.

### The dependency flags

Four Go modules are flagged. Three are file-scan artefacts. **One is not**, and it
was misreported in an earlier revision of this page.

#### `golang.org/x/text`, `golang.org/x/crypto`, `modernc.org/sqlite` — artefacts

| Module | Declared licence | What FOSSA matched |
| --- | --- | --- |
| `golang.org/x/text` | BSD-3-Clause | CC-BY-SA notices in bundled Unicode data files |
| `golang.org/x/crypto` | BSD-3-Clause | An OpenSSL/SSLeay reference; no such licence text exists in the module |
| `modernc.org/sqlite` | BSD-3-Clause | Bundled `LICENSE-SQLITE` and `LICENSE-SQLITE_VEC` notices |

None of these contributes licensed material to a released artefact. Concluding
each as `BSD-3-Clause` is well founded.

#### `modernc.org/libc` — needs legal review

`modernc.org/libc` declares BSD-3-Clause, and its `LICENSE-3RD-PARTY.md` lists
only Go (BSD-3-Clause), musl libc (MIT), go-netdb and NixOS/nixpkgs.

That notice is incomplete. The package is generated by `ccgo`, which transpiles
system headers, and the generated Go files carry the licence comments of the
headers they came from. Measured at v1.74.4:

| Where the copyleft text lives | Files | Reaches a Linux release? |
| --- | --- | --- |
| `testdata/` (crlibm test suite, GPL) | 1 | No — never compiled |
| `*_darwin_*.go` (Apple headers, APSL) | — | No — build constraints exclude them from Linux |
| `*_illumos_*.go` (illumos headers, CDDL) | — | No — build constraints exclude them from Linux |
| `*_linux_amd64.go`, `*_linux_arm64.go` **with** an exception | 20 | Yes — GCC Runtime Library Exception or LLVM Exception |
| `*_linux_amd64.go`, `*_linux_arm64.go` **without** an exception | **32** | **Yes** |

The 32 are transpiled from **glibc** headers and carry the GNU C Library's
LGPL-2.1 notice verbatim. They compile into `ghcr.io/ilavrita/ilavrita` for both
published architectures. Examples: `pwd`, `grp`, `termios`, `dirent`, `unistd`,
`fcntl`, `poll`, `time`, `sys/stat`, `sys/types`, `wctype`, `langinfo`.

What they contain is the ABI surface rather than glibc's implementation —
`pwd/pwd_linux_amd64.go`, for instance, is 789 lines holding 72 type declarations
and 27 constants, and no functions.

**Engineering conclusion:** LGPL-2.1 is compatible with AGPL-3.0, so the AGPL
distribution raises no new obligation. The open question is the **commercial
licence** Ilavrita intends to offer alongside it (PRD risk R-006): relicensing a
product that carries LGPL-derived material you do not own is exactly the case
that risk describes.

**This needs a lawyer, not a scanner.** Do not mark `modernc.org/libc` as
BSD-3-Clause to clear the checks — that would record a conclusion this page's own
evidence contradicts. Options worth putting to legal review:

1. Accept it. Header-derived type and constant declarations are widely treated as
   interface facts rather than protectable expression, and glibc's own position is
   permissive about headers.
2. Avoid it. `modernc.org/sqlite` is the only reason `libc` is present. A
   CGo-backed SQLite driver, or a different storage backend, removes the question
   — at the cost of the pure-Go single-binary property that
   [ADR 0002](adr/0002-build-on-a-pocketbase-fork.md) selected PocketBase for.
3. Scope it. Offer the commercial licence only for deployments where the
   obligation does not arise.

Until that review happens, the AGPL distribution is unaffected and these issues
should stay open in FOSSA, where they are visible.

#### Correction

An earlier revision of this page stated that the GPL and APSL text in
`modernc.org/libc` lived only in `testdata/` and `*_darwin_*.go`, and was
therefore excluded from Linux builds by build constraints. That was checked for
darwin and generalised without checking the Linux files. It was wrong: 52 files
that do compile on Linux carry copyleft notices, and 32 of those carry no
exception.

### The one genuine finding

| Advisory | Package | Severity | State |
| --- | --- | --- | --- |
| [CVE-2023-36308](https://nvd.nist.gov/vuln/detail/CVE-2023-36308) | `github.com/disintegration/imaging@v1.6.2` | Medium | Open, no fixed version |

A crafted TIFF file can crash the decoder. The dependency reaches us through
PocketBase, which uses it for thumbnail generation, and upstream has published no
fixed release.

No Ilavrita route reaches the decoder today, because `/fhir/R4` exposes no image
handling. That changes when Binary and DocumentReference payloads are implemented
(FR-032) — untrusted clinical documents are exactly the input this advisory is
about — so it is a **release gate for any build that accepts uploaded images**.

## Clearing them

FOSSA's REST API is read-only for issues. Verified 2026-09-14 against fourteen
endpoint variants: every issue read succeeds, every issue write returns `404`,
and policy writes return `403 User not permissioned`. The work below has to be
done in the FOSSA dashboard.

It is smaller than the issue count suggests. The ten "Denied by Policy" issues
sit on **three packages**, and FOSSA applies a licence conclusion per package —
so that is three actions, not ten.

### 1. Conclude three dependency licences

For each package below, open it in the project's dependency list, choose
**Conclude licence**, set `BSD-3-Clause`, and paste the note.

| Package | Note to paste |
| --- | --- |
| `golang.org/x/text@v0.42.0` | Module is BSD-3-Clause ("Copyright 2009 The Go Authors"). The CC-BY-SA notices are in bundled Unicode data files, not the licence grant. |
| `golang.org/x/crypto@v0.57.0` | Module is BSD-3-Clause. It contains no OpenSSL or SSLeay licence text; the match is spurious. |
| `modernc.org/sqlite@v1.57.0` | Module is BSD-3-Clause ("Copyright (c) 2017 The Sqlite Authors"). The flags come from bundled `LICENSE-SQLITE` and `LICENSE-SQLITE_VEC` notices. |

**Do not conclude `modernc.org/libc`.** Its flags are not artefacts — see
[above](#modernclibc--needs-legal-review). Leave those issues open until the
commercial-licence question has had legal review.

### 2. Resolve the two AGPL self-flags

These are on Ilavrita itself, not a dependency. Resolve with: *this is the
project's own declared licence.*

### 3. Leave CVE-2023-36308 open

It is real, it has no fixed version, and it should stay visible until upstream
publishes one or the dependency is replaced.

### Why the policy is not being changed

The project is assigned FOSSA's **Standard Bundle Distribution** policy, which is
the right one: Ilavrita ships binaries and container images rather than running
as a hosted service, so distribution-mode obligations apply.

Loosening the policy to permit copyleft would clear these checks and would be the
wrong fix twice over. It would mask a genuinely GPL-licensed dependency arriving
later, and Ilavrita intends to offer a commercial licence alongside the AGPL
(PRD risk R-006) — a copyleft dependency we do not own would block exactly that.

## Running a scan locally

```bash
export FOSSA_API_KEY=...
fossa analyze
fossa test
```

[`.fossa.yml`](../.fossa.yml) scopes this to the two manifests Ilavrita ships. The
CLI reports into a different project from the GitHub App, so prefer the App's
results as the source of truth; CI does not run the CLI, to avoid two projects
disagreeing about the same code.

## When a new finding appears

1. Establish the module's **declared** licence before reacting to a file match.
2. Decide whether the flagged code is compiled into a released artefact.
3. Either remove the dependency, or record the determination here.

A finding that is neither fixed nor written down here is not resolved.
